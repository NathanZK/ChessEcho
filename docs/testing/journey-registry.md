# User Journey Registry

This registry documents the ten canonical user journeys in ChessProbe, establishing their originating requirement provenance, user entry points, primary goals, observable outcomes, implementation status, and confirmed defects or product decisions.

Detailed visual flowcharts for each journey are documented in [docs/testing/user-journey-flowcharts.md](user-journey-flowcharts.md).

## 3. Product Owner Decision Registry

The following decisions require explicit product-owner direction before downstream test automation (Phases 1–7):

1. **PO-DEC-01 (Guest vs. Authenticated Import Concurrency Conflict)**: When an active guest import is running for a username, should an authenticated user connecting that same account be blocked with 409 conflict, or should the existing job be adopted?
2. **PO-DEC-02 (Practice Carousel Index Persistence)**: Should the in-flight puzzle carousel index be persisted in `sessionStorage` across browser refreshes (`F5`)?
3. **PO-DEC-03 (Similar Positions Timeout Retry Enhancement)**: When Stockfish dynamic reranking times out and falls back to static BM25 ranking, should an interactive "Retry Dynamic Analysis" button be surfaced to the user as a future enhancement?
4. **PO-DEC-04 (Multi-Tab Session Synchronization Enhancement)**: Should cross-tab session logout be synchronized in real time via `BroadcastChannel` or `storage` events, or is request-time 401 expiration acceptable?
5. **PO-DEC-05 (Evaluation Horizon Notice)**: When engine evaluation loss is null due to losing-mate horizon defense, should an informational coaching notice be displayed to explain why alternative moves are rejected?
